# 07 — Pioneers and reference works to look up to

Research date: 2026-10-20. Every link was checked on 2026-10-20 with WebFetch (marked **F**) or confirmed only through search results (marked **S**, meaning the page appeared in results but was not opened). Anything not confirmed is flagged in the "Unverified / caveats" section. Star counts are as of 2026-10-20.

The project: "a personal health agent that keeps score." It is an ADK multi-agent system over real Google Health API data plus a mood/energy journal. Its features are a calibrated forecast ledger, code-execution receipts, PHIA-style ablations, a single- vs multi-agent baseline, a calibrated LLM judge, a read-only MCP server, OTel tracing, red-teaming, and a Cloud Run synthetic-twin demo.

## Short notes: methodological cautions to state in the README

1. **Correlation is not an n-of-1 trial** (AHRQ guide, Daza, Gelman on Roberts). The agent should label observational findings as hypotheses and propose a randomized ABAB block to test them.
2. **Multiple comparisons** (Gwern). If the agent scans 40 metrics against mood, apply BH correction or report how many tests were run.
3. **Reactivity** (BBS commentary on Roberts; EMA literature). Journaling and forecasting can change the very state being measured. Note this as a known confound.
4. **Non-exchangeability** (conformal). Daily series are autocorrelated, so use rolling-origin evaluation (fpp3) and adaptive conformal.
5. **Beat the naive baseline or say so** (fpp3, Gneiting and Raftery). A ledger that loses to "same as yesterday" is still a publishable, honest result.
6. **Judges need their own evals** (Husain/Shankar, EvalGen, Anthropic). Report the judge's TPR/TNR on held-out labels you wrote yourself.
7. **Multi-agent is a hypothesis, not a default** (Anthropic; Cognition; Google scaling paper). The single-agent baseline is the experiment.
